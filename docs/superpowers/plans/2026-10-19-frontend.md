# HARU 프론트엔드 구현 계획 (Plan 2/2: Frontend)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (inline) or superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** 승인된 Figma 디자인(손님 6개, 어드민 3개 화면)을 Next.js로 구현하고 완성된 FastAPI 백엔드에 연결해서, 대실·숙박 예약과 어드민 관리가 브라우저에서 끝까지 동작하게 만든다.

**Architecture:**
- `frontend/`에 Next.js 앱 하나를 두고 App Router를 쓴다. 손님 화면은 `(site)` 라우트 그룹, 어드민은 `admin/` 아래에 둔다.
- 브라우저는 `/api/*`와 `/uploads/*` 요청을 Next rewrites로 백엔드에 넘긴다. 그래서 같은 출처로 동작하고 httpOnly 쿠키가 그대로 쓰인다.
- 데이터는 클라이언트 컴포넌트에서 TanStack Query와 `openapi-fetch`로 가져온다. 타입은 OpenAPI에서 생성한다.
- 비즈니스 규칙은 다시 구현하지 않는다. 가능 여부와 가격은 항상 API(`/availability`, `/quotes`)가 정답이다.

**Tech Stack:** Next.js 16.4 (App Router, `proxy.ts`), React 19, TypeScript, Tailwind CSS 4.3 (CSS-first `@theme`), TanStack Query 5, openapi-typescript 7 + openapi-fetch 0.17, lucide-react(Figma와 같은 아이콘셋), Vitest 5 + Testing Library + jsdom, Playwright 1.64.

**Spec:** `docs/superpowers/specs/2026-10-19-hotel-booking-design.md`
**Design:** https://www.figma.com/design/8rIYX31Lxdsoy8eHinf4ub (fileKey `8rIYX31Lxdsoy8eHinf4ub`)
**Backend:** `docs/superpowers/plans/2026-10-19-backend.md` (완료). API 문서는 `http://localhost:8000/docs`에 있다.

## Review Focus
1. **브라우저 시간대가 KST가 아닌 경우**(예: `America/Los_Angeles`): 시각은 여전히 15:00로 보여야 한다. 달력의 오늘과 지난 날짜도 KST 기준이어야 한다. 테스트: Task 1(Vitest를 `TZ=America/Los_Angeles`로 실행)과 Task 11(Playwright `timezoneId`).
2. **오래된 화면에서 결제**: 슬롯이 가능으로 보였는데 결제 직전에 다른 사람이 예약했다면 409 `SLOT_UNAVAILABLE`이 온다. 이때 "방금 다른 예약이 들어왔어요" 안내를 보여주고 예약 화면으로 돌려보낸다. availability 쿼리는 다시 불러온다. 테스트: Task 6.
3. **비로그인/세션 만료 상태로 결제 화면 진입**: `/login?next=<원래 URL>`로 보낸다. 로그인 후에는 선택한 내용이 그대로 남은 결제 화면으로 돌아와야 한다. 테스트: Task 3(proxy)과 Task 11(E2E).
4. **숙박 기간 선택의 예외 입력**:
   - 체크인보다 앞 날짜를 누르면 그 날짜가 새 체크인이 된다.
   - 마감일을 사이에 둔 범위는 만들 수 없다.
   - 최대 연박을 넘는 범위는 만들 수 없다.
   - 최종 판정은 quote의 `available`과 `reason`으로 한다.

   테스트: Task 5(순수 reducer).
5. **결제 버튼 연타**: 요청은 정확히 1번만 나가야 한다(pending 동안 버튼 비활성). 테스트: Task 6.
