## 설계 (spec 요약 — 레포에 저장할 내용)
- **시간 구간 모델**: 모든 예약은 `[start_at, end_at)`로 저장하고 `blocked_until = end_at + cleaning_buffer`를 같이 저장함. 버퍼는 **끝에만** 붙음. 겹침 판정은 `tstzrange(start_at, blocked_until, '[)')`로 함.
  - 숙박 11:00 체크아웃이면 12:00부터 대실 가능.
  - 대실 10–14이면 15:00부터 숙박 체크인 가능.
- **DB 제약**: `EXCLUDE USING gist (room_id WITH =, tstzrange(start_at, blocked_until, '[)') WITH &&) WHERE (status = 'CONFIRMED')`, `btree_gist` 확장 사용.
- **차단 일정** = `reservations.type = 'BLOCK'` 행이고 `user_id`는 NULL, `total_price`는 0, `blocked_until = end_at`(버퍼 없음). 같은 제약이 예약↔차단 겹침도 막아줌. (기존 계획의 `room_blocks` 별도 테이블 대신 이 방식으로 바꿈. 이유: 테이블이 따로 있으면 두 테이블에 걸친 경쟁 조건이 생김.)
- **상태**: 저장하는 값은 `CONFIRMED`와 `CANCELLED`뿐임. API는 `display_status`를 계산해서 줌. `CONFIRMED`이면서 `end_at <= now`이면 `COMPLETED`이고, 이걸 위해 배치 작업을 두지 않음.
- **기본 설정값** (`room_settings` 단일 행, 어드민에서 수정):

  | 항목 | 키 | 값 |
  |---|---|---|
  | 대실 요금 | `dayuse_weekday_price` / `dayuse_weekend_price` | 35000 / 45000 |
  | 숙박 요금 | `stay_weekday_price` / `stay_weekend_price` | 79000 / 89000 |
  | 대실 입실 가능 시각 | `dayuse_first_start_hour` ~ `dayuse_last_start_hour` | 10 ~ 20 |
  | 대실 이용 시간 | `dayuse_hours` | 4 |
  | 숙박 체크인 / 체크아웃 | `stay_check_in_hour` / `stay_check_out_hour` | 15 / 11 |
  | 최대 연박 | `stay_max_nights` | 7 |
  | 청소 버퍼 | `cleaning_buffer_minutes` | 60 |
  | 손님 취소 마감 | `guest_cancel_deadline_hours` | 24 |
- **주말 판정**: 대실은 날짜가 토·일(`weekday() in (5,6)`)이면 주말, 숙박은 각 박의 날짜가 금·토(`weekday() in (4,5)`)이면 주말.
- **시간대**: DB는 `timestamptz`(UTC)로 저장하고, 날짜·시각 규칙은 모두 `Asia/Seoul` 기준임. API 응답 datetime은 `+09:00` 오프셋으로 직렬화함. "오늘"은 서버 TZ와 상관없이 KST로 계산함.
- **결제**: `PaymentProvider` 프로토콜과 `MockPaymentProvider`를 둠. 예약 생성 요청 1번에 예약 행과 `payments(status='PAID')`가 함께 생성됨. 취소하면 payment는 `REFUNDED`가 됨.
- **취소 규칙**: 손님은 `now <= start_at - guest_cancel_deadline_hours`일 때만 취소 가능하고, 경계값과 같아도 허용함. 어드민은 시작 전이면 언제든 가능함.
- **인증**: JWT(HS256, `sub=user_id`, `role`)를 httpOnly 쿠키 `haru_session`에 담음(SameSite=Lax, 만료 24h). 프론트는 Next rewrites로 `/api/*`를 백엔드로 프록시해서 같은 출처로 동작함. 모든 라우트는 `/api` 접두사 아래에 둠.
- **예약 코드**: `HR-{start_at KST %m%d}-{id:04d}` (예: `HR-1023-0012`).
- 디자인 토큰과 폰트(Noto Sans KR, Gowun Batang)는 Plan 2에서 사용함.

## Review Focus
1. **연박 중간날의 짧은 대실**: `dayuse_hours=2`일 때 10/24 12–14 대실(blocked ~15:00)이 있으면, 1박 단위로는 10/23·10/24 모두 가능하지만 10/23~10/25 2박은 겹침 → quote는 `available=false`, 생성은 409. 이 테스트는 Task 5와 Task 6에 둠.
2. **KST 날짜 경계**: now가 `2026-10-19 00:30 KST`(UTC로는 10/18)일 때 10/19 대실 조회와 예약이 "오늘"로 처리돼야 함. 지난 시각 슬롯만 막혀야 함. 테스트는 Task 2와 Task 5에 둠.
3. **설정 변경 후 기존 예약**: 버퍼를 60분에서 120분으로 바꿔도 기존 예약의 `blocked_until`은 그대로이고 새 예약에만 적용됨. 테스트는 Task 8에 둠.
4. **취소 마감 경계**: `start - 24h`와 정확히 같은 시각이면 허용, 1초 지나면 409 `CANCEL_DEADLINE_PASSED`. 테스트는 Task 6에 둠.
5. **중복 제출/경쟁**: 같은 슬롯에 동시 요청 2개가 오면 하나는 201, 하나는 409(500 아님). 테스트는 Task 3(DB 레벨)과 Task 6(API 레벨)에 둠.
